# 賭場機器人公告

產品版本以 `package.json` 為準。正式服以同一個「🎲命運荷官」Bot 發送得獎與出入場公告；使用 REST API，不需要 Gateway 常駐在線。遊戲與管理指令仍走 HTTP interactions。入場登記先確立帳目起點，Discord 訊息則由背景佇列傳送。

## 玩家看到的內容

| 項目 | 觸發／文案 | 圖片 |
|---|---|---|
| BIG WIN | 派彩達總下注 10 倍至未滿 30 倍；`@玩家，這局手氣不錯！` | 右側原方圖、暖金倍率 |
| SUPER WIN | 30 倍至未滿 100 倍；`@玩家，這局贏得漂亮！` | 原橫幅、香檳金倍率 |
| MEGA WIN | 100 倍以上；`@玩家，中了大獎！這局值得拍手。` | 原橫幅、玫瑰紅倍率 |
| 入場 | `♠ 入場 · @玩家，歡迎來玩！` | 無 |
| 正常離場 | `♣ 離場 · @玩家 離開賭場` | 有下注時附黑金收據 |
| 連線到期 | `♣ 離場 · @玩家 暫時離開賭場` | 有下注時附黑金收據 |

每局只發最高得獎級別的一則公告，例如 `BIG WIN · 15×`。Discord 的原生色條只影響卡片左側；卡內倍率由伺服器依實際結果繪製，附上包含級別與倍率的替代文字。一般獲獎不公告。玩家標記使用已驗證 ID，禁止 everyone、角色及名稱自行解析。未設定靜音旗標，但實際手機提醒仍由玩家的 Discord 通知設定決定。

大獎、野球拳通關和離場結算卡下方有與 `/戲籌` 同款藍色的「開啟遊戲」按鈕。獲得戲籌卡採黑金收據，不附遊戲按鈕。正式服沿用既有指令，不新增私人預覽指令。

1.1.1 的離場收據呈現本次合計及實際玩過的遊戲：老虎機局數、野球拳入場與通關次數。正數紅字加號、負數綠字減號、打平金色。數據來自入場後的權威結算，排除簽到及管理員發放／更正；跨次遊玩的野球拳只計本次實際扣款與獎金。新版部署前已入場且沒有帳本起點的租約，保留原老虎機收據至離場，避免推算不存在的數字。未下注仍以一行文字通知。

野球拳通關使用五位角色的核准留影卡；獎金、勝數與玩家標記來自結算結果。通關事件和獎金在同一 Firestore 交易建立，原請求重試不重複建立公告。

## 總投入排行榜

雙遊戲大廳的獎盃在背景音樂旁。左側「月排名」和右側「總排名」各有總投入、老虎機、野球拳三張榜，每頁十名。每張榜都列出本群有錢包的玩家，尚無投入顯示 0。投入取已結算的老虎機下注及野球拳入場費。同額以 Discord 玩家 ID 排定固定順序。月排名從最近一次成功的「全群重設戲籌」起算，總排名從開服累積。首次重設前兩個期間相同。重設保留開服累積。

排行榜優先顯示 Discord 群內暱稱，其次是 Discord 顯示名稱或帳號名稱。玩家登入時同步名稱，已綁定同一應用程式的 `DISCORD_BOT_TOKEN` 時也可查詢尚未登入的歷史玩家。測試服停用公告時仍可查詢名稱。

榜單從既有備份建表，之後沿用已提交的帳本在 Durable Object 的 SQLite 更新。查榜不讀寫 Firestore。背景每批處理 128 筆，記憶體保留 512 筆；重啟或溢出時只補讀缺號，失敗後等 30 秒重試。同群同榜共用頁面快取，最多 64 頁。建榜中或落後超過 128 筆時會提示稍後重試；其餘時間顯示最近完成的排名。

遊玩期間照常更新排行榜。離場結算後，命運荷官把玩家這次遊玩的各榜晉升合併成一張黑金小卡，在現有遊玩頻道發送。卡片列出玩家和各榜單的原名次、新名次及上升幾名。有多個榜單晉升時，圖片呈現上升最多的那一組。首次重設前兩個期間合併呈現。切換遊戲或另有活動分頁仍在遊玩時，這次遊玩會繼續累積。初次取得名次、歷史資料建榜及全群重設本身不發廣播。

正式服排行榜廣播使用 `DISCORD_LEADERBOARD_ROLE_ID` 指定「試運者｜Aleator」身分組。Bot 只會通知該身分組。測試服可使用下方的文字標籤設定。大廳排行榜可獨立於廣播使用。

本機以專案指定版本的 Node 執行 `node scripts/preview/leaderboard.js`，開啟 [排行榜預覽](http://127.0.0.1:4207/leaderboard-preview.html)。從「本機測試工具」模擬兩款遊戲的名次晉升及月重設。預覽使用 13 名示例玩家及本機 Discord 模擬器。

## 程式與素材

| 位置 | 責任 |
|---|---|

| `server/discord/discord-win-card.js` | 將實際倍率繪在卡片上；由 `python scripts/assets/build-discord-win-card.py` 從原圖重建素材 |
| `server/discord/player-display.js` | 安全名稱、玩家標記與允許通知的 ID |
| `server/discord/casino-bot.js` | Bot 身分／目的地驗證、REST 傳送、限流 |
| `server/discord/casino-visits.js` | 出入場租約、帳目摘要、持久佇列與狀態 |
| `server/discord/arcade-receipt.js` | 依本次雙遊戲帳目產生動態 PNG 與替代文字 |
| `server/discord/casino-receipt.js` | 發放收據與部署前既有租約的相容收據 |
| `server/firestore/duel-announcements.js` | 權威通關 outbox、持久等待與結果不明隔離 |
| `scripts/assets/build-casino-receipt.py` | 以 Windows 字型與 Pillow 重建收據底圖及數字字形 |
| `src/platform/casino-presence.js` | 瀏覽器心跳、關閉、返回頁面 |
| `public/announcements/` | Discord 使用的公開無損 WebP |
| `art/announcements/` | BIG 原尺寸無損母檔，不公開部署 |
| `docs/data/announcement-art.json` | 尺寸、檔案／像素雜湊與編碼紀錄 |

同一位荷官的三張核准插圖維持原設計。SUPER／MEGA 為 1671 × 941，WebP 與原 PNG 逐像素相同；BIG 保留 1254 × 1254 母檔，公告版先縮至 384 × 384，再無損編碼（215,632 bytes）。縮尺寸會改變像素，公告版的無損保證是相對於縮圖，不是原尺寸。Discord 代理的顯示縮圖另由平台處理。

公開網址以內容雜湊命名；換圖時同步更新 `HIGHLIGHT_ART` 與圖片紀錄。圖片不進入遊戲開場預載。符號只保留相關撲克牌花色與 Bot 名稱的骰子，不堆疊 Emoji。

## 連線、可靠性與用量

- 雙遊戲由大廳統一持有一段遊玩：完成登入後先登記帳目起點，再開放遊戲入口。切換老虎機、野球拳或返回大廳不重複進離場；心跳與離場沿用大廳的登入續期。舊版獨立老虎機仍自行管理進離場，未啟用 Bot 的測試服不送出這些請求。
- 每 45 秒心跳；租約 180 秒，最後分頁關閉後保留 10 秒重連寬限。同一玩家多裝置合併一段遊玩，隱藏分頁不等於離場；手機凍結或網路中斷可能觸發到期公告。
- 心跳只更新 DO 狀態；入場、離場才讀權威帳目。離場等待已接受的結算。瀏覽器不能指定身分、餘額或輸贏；返回頁面的舊請求也不能影響新連線。
- 得獎事件與下注交易一起存入 Firestore outbox，`recipientId` 使用已驗證玩家。備份還原從原回合擁有人重建；七表格式不變。沒有可驗證 ID 的舊事件只顯示安全名稱。
- 429 依持久等待時間重試，固定 nonce 防止近期重送；POST 結果不明或中途重啟標為 `uncertain`，不自動重貼。Discord 傳送失敗不回滾結算；不保證外部網路故障下每則必達。
- 出入場上限為 128 個同時遊玩帳號、每帳號 8 分頁與 256 筆事件。優先移除已送達紀錄，不丟棄待發事件；達上限暫緩公告。這是保護上限，不是免費方案容量保證。
- 私有維運狀態只含活躍、待發、最早待發時間與結果不明數量。出入場等待超過十分鐘或結果不明時，獨立監控依既有連續兩次規則提醒人工核對。
- Worker／DO 操作、帳目摘要與 outbox 都計入原額度，不提高或重設預算。BIG 理論上約占 1.2726% 回合，每千局平均增加約 12.7 則；實際短期次數會浮動。

出入場操作狀態與獨立的 `duelAnnouncements` 傳送佇列不屬於七表帳本備份；災難恢復不重播舊出入場／通關公告，遊戲與派彩仍由原收據完整恢復。通關傳送的 429 等待持久保存；過期傳送租約標記結果不明，不盲目重貼。舊 Webhook 模式仍保留十分鐘合併、限流與靜音行為，不能與 Bot 同時設定。

入離場沿用唯一 writer 的已提交錢包快取及原有最長 30 秒有效期；過期、失效或時鐘倒退必須重讀。野球拳收據只查本次入場起點之後的分類帳目，不掃描玩家全部歷史。所有額度、結算順序與權限檢查保留。

## 部署與驗收

正式服使用 `deploy/casino-bot.env.example`，啟用前核對 Bot 安裝、私密 Token、群與頻道。公告頻道需要檢視頻道、傳送訊息、嵌入連結及附加檔案（52224）。已安裝的正式 Bot 如只具備舊的 19456 權限，發布黑金收據前須先在公告頻道補上「附加檔案」。沿用既有 Worker、DO、namespace、Secrets 與額度。

### Discord 測試服

- 在 [#工程師的專屬地](https://discord.com/channels/760012177326997544/1564243344857632818) 執行 `/推播預覽` 並選擇樣式。這是測試 App 專用的私人回覆，使用示例數據，可看入場、未下注離場、三種大獎、獲得戲籌、五位角色的通關留影，以及混玩、只玩老虎機、只玩野球拳三種離場收據。新版收據取代原本「這次賺了／賠了／打平」的預覽選項。卡片上的按鈕會開啟測試版遊戲。註冊入口為 `node scripts/discord/register-casino-preview.js`。
- 連線到期提供未下注和附離場收據兩種預覽。「排行榜｜名次晉升」的黑金小卡列出示例玩家、前後名次和上升幾名。
- 通關留影採角色登場圖，保留通關勝場與角色配色；收據以合計為主，只列實際遊玩的遊戲。示例以派彩減老虎機下注及野球拳入場費，不含簽到與管理員發放。通關卡預繪成無損 WebP；收據以預繪底圖與字形產生 PNG，共用 Noto Sans TC、Noto Serif TC、Georgia 字型和配色，以附件更新原本的私人回覆，正文與替代文字也提供完整數據。重建素材使用 `node scripts/assets/build-casino-preview-art.js`（Windows 設計字型、Playwright Chromium 與 Python Pillow）。
- 「獲得戲籌」預覽沿用大獎卡的附件做法，採黑金收據外框並顯示範例金額、發放原因與紀錄編號。卡片不附遊戲按鈕。私密回覆顯示執行者的 @ 樣式，不會觸發提及通知或發放戲籌。
- 測試 Worker 使用 `DISCORD_COMMAND_PROFILE=test-parity`。`/戲籌`、`/戲籌管理`、雙遊戲營運和玩家回報使用與正式服相同的流程及權限檢查。`/推播預覽` 仍是測試 App 的私人示例。
- 測試服公開通知使用測試 App 自己的 `DISCORD_BOT_TOKEN`。入場、離場、大獎、通關和發放通知沿用正式流程。排行榜在測試群以 `DISCORD_LEADERBOARD_TEXT` 顯示「@試運者」文字。有設定本群的通知身分組 ID 時，改用該身分組提及。
- 測試 Bot 只接受單一測試群，公告頻道須和指令允許清單的唯一文字頻道 `1564243344857632818` 一致。部署前用 `arcade:preflight -- test` 核對測試 App、群、頻道及環境。測試服公開通知使用專屬 Bot，測試與正式的憑證、頻道及身分組各自設定。

出入場整合在 Cloudflare runtime，本機 Node／SQLite QA 不對真實頻道發送。以隔離資料驗證得獎、去重與恢復；正式環境唯讀檢查健康、指令與圖片。真人確認登入、入離場與手機提醒，不以正式下注製造測試大獎。部署現況見[客戶交付](customer-handoff.md)，測試見[驗收文件](testing.md)。
