# 野球拳通關機率

每位角色固定一組規則，沒有獨立難度。入場基準為 1,000 戲籌，通關獎金是整場總獎金，不另退入場費。本機預覽不扣款、不發獎入帳；獨立測試雲端由伺服器扣費、抽拳與發獎，兩者共用勝敗推進函式。CG 收藏與單場紀錄不參與機率抽樣。模式及資料邊界見[野球拳流程](yakyuken-preview.md)。

每拳獨立，玩家選任何手勢都使用同一組機率。使用 Web Crypto 的 uint32 亂數，以拒絕取樣消除對 10,000 取餘數的偏差；先抽勝／敗／平手，再決定符合結果的荷官手勢。不依勝敗進度、玩家手勢、重開、造型或歷史調整權重。平手不計入勝敗、不另收費；勝場累積，不要求連勝。

測試雲端的新場次在確認入場時，使用上述原抽樣器按序預抽到通關或失敗，將整場序列和扣費放入同一提交；不另外抽一次整場通關，也不截斷平手。只是把相同獨立亂數提早使用，沒有改變每拳或整場機率。序列不放入公開錢包，前端只收到下一拳的固定結果與順序；玩家確認手勢後才配出符合結果的荷官手勢。入場／出牌重試、重載與跨裝置均沿用原場次。部署前已付費的舊場次維持原逐拳抽樣直到結束；本機無錢包預覽仍使用相同權重逐拳抽樣。

每次確認只推進同一拳，玩家出牌、荷官跟牌與翻牌同步開始，翻牌規劃為 150ms 收合＋180ms 展開；畫面計分在揭曉時更新。已備妥的權威結果可先呈現，進度與派彩確認同時送出；確認前不能繼續出拳、換裝、顯示已入帳或啟動領獎。縮放、減少動態與切換背景只完成同一份結果，不重抽。到達任一門檻即終止，不能續打或重複結算；勝敗均提供「再次挑戰」開始同角色新場，或「返回」回到荷官選擇，不再自動離開敗場。測試雲端新場仍由伺服器扣一次入場費；返回不另扣費、退費或發獎。完成或離場即移除整場私有預抽序列。本機收藏／紀錄模組另保存 CG 解鎖及每場勝敗統計，不保存逐拳歷史，也不改變任何權重。

驗算：去掉平手後，單拳勝率為 `p = 每拳勝率 / 0.8`。取得 `W` 勝前少於 `L` 敗的通關率為 `Σ(k=0..L−1) C(W+k−1,k) × p^W × (1−p)^k`；系統淨回收率為 `1 − 通關率 × 獎金 / 1000`。`characterOdds()` 使用動態規劃，測試以獨立的決勝序列枚舉交叉核對。

角色一為命運荷官（`dealer`），角色二為優然（`guest-1`），角色三為夏澄（`guest-2`），角色四與五仍準備中。門檻、獎金、權重及開放狀態只存放於 `characters.js`；選角、規則視窗、計分與挑戰引擎共用，不能把角色一切換成其他角色的機率。五組機率由引擎單元測試完整驗證；瀏覽器測試僅允許實際已開放角色入場。
